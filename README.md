# GrowthTrack: Student Success Platform

GrowthTrack is a campus student-success platform built with **Next.js, React, TypeScript and Supabase**. It gives every role on campus
a workspace of its own (administrator, faculty mentor, Head of Department, Training and Placement Officer, student) and adds
**predictions, recommended actions and an executive brief** on top of the usual academic, attendance and placement tracking.

> **All data is synthetic.** The 800 students, their marks and their outcomes were generated by rules we designed
> (see [`data/DATASET.md`](data/DATASET.md)). Model scores show that the pipeline works end to end; they are not a claim about accuracy on real
> students. Retrain on your institution's own records before any decision depends on the output.

## Features

### For every staff role
- **Role workspaces** with their own sidebar, drawn by one shared layout. A role sees only its own links and its own students.
- **Forecast** for next semester per student: expected SGPA with a range, backlog risk, placement readiness and engagement drop, each with
  Low / Medium / High levels, plain-language reasons (drivers) and a **what-if** panel that re-scores a student when attendance, assignments,
  coding, interview or LMS inputs change.
- **Recommendations board**: every action names the student or group, why (linked to the model's drivers), who owns it, how urgent it is and its
  status (open, accepted, done, dismissed). Grouped by priority, shortened to bullets, filterable by department, segment, owner, priority,
  status and outcome. Status changes are saved and everyone sees them.
- **Risk trends**, **Segments** (six student groups with a suggested action each) and **Model performance** (metrics against baselines, calibration,
  fairness checks and the main drivers).
- **Analytics Copilot**: a floating assistant that answers questions about the students in the signed-in person's own scope, from the database.
- **Executive brief**: a four-minute slide deck built from live data, viewable in the app and downloadable as PowerPoint.

### Administrator
- Overview with the forecast block, risk distribution, student groups, students needing attention and department comparison.
- Students directory (add a student from the app, or in Supabase, and it appears straight away), academic performance, results, attendance management,
  placement readiness, interventions (the "Create action plan" button scrolls to a pre-filled form), skill gap and settings.

### Faculty mentor
- Overview of their own mentees with the forecast and the actions waiting for them, plus the shared working pages.

### Head of Department (HOD)
- Department overview, faculty overview (mentees and risk per mentor), student performance, attendance analytics, academic results.
- **Student feedback control**: feedback is locked for students until the HOD opens it, with an optional message and closing date.
  Students are notified when it opens.

### Training and Placement Officer (TPO)
- Placement overview, placement readiness per student, strong and weak areas, students needing support (with suggested training), placement analytics.
  A student with no assessment is "Not assessed", never scored zero.

### Student portal
- Home (success plan first, success score and breakdown, academics, career readiness, engagement), attendance (risk cards, subject-wise line graph, plan-ahead
  simulator), results, engagement, placement (aptitude test, mock interview, **soft skills** with situational test and video introduction), skills,
  coding editor (Java, Python, C and SQL with run and submit) and feedback (opens only when the HOD unlocks it).

### Landing page
- Animated, role-based entry (Faculty, HOD, TPO, Student) with 3D hover effects.

## Tech stack

- **Next.js 16** (App Router, Turbopack, `cacheComponents`), **React 19**, **TypeScript**
- **Tailwind CSS 4**, shadcn/ui and Base UI, lucide-react icons, framer-motion, recharts, CodeMirror
- **Supabase**: Postgres 17, Auth and Row Level Security (`@supabase/ssr`, `@supabase/supabase-js`); SWR for data fetching
- **Python** (numpy, pandas, scikit-learn, scipy) for the prediction pipeline; the app itself never runs Python
- **PGlite** for offline database tests, **tsx** to run scripts, **pptxgenjs** for the executive brief

## Getting started

**Prerequisites:** Node.js 20+, npm, a Supabase project. Python 3.9+ is needed only to re-run the prediction pipeline.

```bash
git clone https://github.com/Raj2381/grow-track.git
cd grow-track
npm install
cp .env.example .env.local        # then fill in the values (see below)
npm run db:migrate                # create tables, policies and views
npm run db:seed                   # load 800 students (about 330,000 rows)
npm run db:load-ml                # load predictions, recommendations, segments, trends, metrics
npx tsx scripts/db/e2e-accounts.ts create   # create the demo accounts used by the built-in sign-in
npm run dev                       # http://localhost:3000
```

If you do not set `SUPABASE_DB_URL`, `npm run db:migrate` writes `supabase/all_migrations.sql`; paste it into the Supabase **SQL Editor** and run it
(safe to run again). In the Supabase dashboard, switch **off** "Allow new users to sign up": this app has no public registration.

Optional checks: `npm run db:verify` compares row counts with the source data.

## Environment variables

Copy `.env.example` to `.env.local`. **Never commit `.env.local`.**

| Variable | Where | Purpose |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | browser | Supabase project settings (meant to be public) |
| `SUPABASE_DB_URL` | server only | Connection string used by `db:migrate`, `db:seed` and the brief builder |
| `SUPABASE_SERVICE_ROLE_KEY` | server only | Alternative for seeding and creating logins |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | server only | Optional: AI mock interviews (`gpt-4o-mini` by default) |
| `NEXT_PUBLIC_DEMO_PASSWORD`, `NEXT_PUBLIC_DEMO_{ADMIN,FACULTY,HOD,TPO,STUDENT}_EMAIL` | browser | The built-in demo sign-in (see below) |
| `NEXT_PUBLIC_REQUIRE_AUTH` | browser and proxy | `true` makes the proxy enforce the role routing rules (off by default) |

Anything not prefixed `NEXT_PUBLIC_` stays on the server. Do not put the service-role key or database password in a `NEXT_PUBLIC_` variable.

## Database and security

Supabase Postgres with **Row Level Security on every table** (`npm run test:rls` fails if any table has it off). Roles come from the `profiles` table,
written only by a trigger from `app_metadata` (users cannot edit it), never from `user_metadata`.

| Role | Can read | Can write |
|---|---|---|
| anonymous | nothing | nothing |
| student | own rows, own forecast and recommendations, own department's feedback window | own portal data; never marks, attendance or predictions |
| faculty | their mentees; models and trends | interventions and recommendation status for their mentees |
| hod | every student of their own department | the same for those students, and their department's feedback window |
| tpo | every student, for placement work | recommendation status; no administrator functions, no faculty evaluations |
| admin | everything | staff-managed tables, add students, feedback windows |

Migrations (`supabase/migrations`, applied in order): schema, security and helper functions, attendance and realtime, forecast views, add-student function,
HOD and TPO roles, feedback windows, and `student_summary` (the CGPA and attendance figures that the student portal and staff dashboards share).

Faculty evaluations are anonymous by design: the evaluation row has no student id, a separate receipt row stops duplicates, and staff only see aggregates
of at least five responses.

## Demo sign-in (no login page)

There is no login page. The browser signs itself in to a throwaway account that matches the area it opens: `/hod/*` as the HOD, `/tpo/*` as the TPO,
`/faculty/*` as a mentor, `/student/*` as a student and everything else as the administrator ([`lib/supabase/demo-session.ts`](lib/supabase/demo-session.ts)).

> **Anyone who can open the site can open every workspace.** The demo account details are in the browser bundle by design. Row Level Security still limits
> each account to its own scope and keeps the database closed to visitors without a session, but this setup is for demonstration only. For real use,
> replace `demo-session.ts` with real sign-in and set `NEXT_PUBLIC_REQUIRE_AUTH=true`; the proxy then enforces the routing rules in `lib/access.ts`.

## Predictions and recommendations

`npm run ml:all` turns `data/csv/` into forecasts for four outcomes, plain-language drivers, a what-if re-scorer, segments and prioritised recommendations,
written as static JSON to `public/data/`; `npm run db:load-ml` loads them into Supabase (staff decisions on recommendations are kept).
Results, leakage controls and limitations are in [`ml/README.md`](ml/README.md). The recommendation rules are in
[`lib/recommendations.ts`](lib/recommendations.ts) and the student-facing wording in [`lib/student-advice.ts`](lib/student-advice.ts).

## Deployment

1. Push to GitHub and import the repository into Vercel.
2. Set the environment variables above (server-only ones as non-public variables).
3. Apply the migrations to your Supabase project and load the data (`db:migrate`, `db:seed`, `db:load-ml`).
4. Remember the [demo sign-in](#demo-sign-in-no-login-page) warning before making a deployment public.

## Known limitations

- Several shared staff pages (students list, academic performance, results, placement readiness, attendance analytics, skill gap) still read the bundled
  dataset, and interventions, attendance sessions, declared results and student feedback are stored in the browser. The forecast pages, the overview,
  the HOD, TPO and faculty workspaces and the feedback lock read Supabase.
- The student portal calculates its own success score from the bundled records; staff pages show the model's snapshot, so that one figure can differ slightly.
  CGPA and attendance now come from the same database view in both places.
- Students added later have no forecast until their records are loaded ("awaiting records").
- The demo sign-in is not real authentication (see above).
- `next build` prints a Next.js security advisory for the pinned version; plan an upgrade before production.
